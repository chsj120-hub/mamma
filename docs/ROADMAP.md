## 1. 한눈에 보는 결론

1. **핵심 기능은 대부분 구현됐어요.** 식단 플래너·홈큐브·리포트·마일스톤·출력·CSV·AI 추천·로그인/동기화 코드까지 있어요.
2. **출시·수익화를 막는 건 기능이 아니라 '법적·정책 필수 항목'이에요.** 이용약관·개인정보 처리방침·회원 탈퇴·민감정보(알레르기·건강) 동의가 없고, 이게 없으면 Play 스토어 심사와 광고 승인이 모두 어려워요.
3. **광고 설계가 앱과 PC에서 달라져야 해요.** Play 앱은 AdMob(네이티브 SDK)이 필요해서 지금 웹앱을 그대로 올리는 방식(TWA)으로는 못 붙여요. → **Capacitor 래퍼 권장** (광고·정확한 로컬 알림·네이티브 구글 로그인이 한 번에 해결돼요).
4. **PC 광고는 '로그인 뒤 화면'만으로는 승인·수익이 어려워요.** 검색·카페에서 들어올 **공개 페이지(월령별 가이드 등)**와 자체 도메인이 필요해요.
5. **"가입은 모바일에서만" 규칙이 PC 배포 전략과 충돌해요.** 맘카페에서 PC로 들어온 사람이 가입을 못 하면 바로 이탈해요. (아래 §6 결정 1)

## 3. 수익화를 고려한 설계

### 3-1. 배포 방식 (플랫폼별)

| | 모바일 앱 (Play 스토어) | PC (맘카페 배포) |
|---|---|---|
| 형태 | **Capacitor로 감싼 Android 앱** | 웹 + (설치형 PWA) |
| 광고 | **AdMob** (네이티브 SDK) | **카카오 AdFit**(국내 소형 사이트에 흔함) 또는 AdSense |
| 로그인 | **네이티브 구글 로그인 플러그인** | 웹 팝업 (현재 구현) |
| 알림 | **로컬 알림 예약** → 앱이 닫혀도 울림 | 탭이 열려 있을 때만 |
| 비고 | 계정 개설비 1회 + 비공개 테스트 요건 | **자체 도메인** 필요 |

**왜 TWA(웹앱 그대로 올리기)가 아닌 Capacitor인가**
- AdSense(웹 광고)는 앱에서 쓰지 못하고, 앱 광고는 AdMob SDK가 필요해요 → TWA로는 광고를 못 붙여요.
- 앱 안 웹뷰에서는 **구글 로그인이 막혀요**(구글 정책). 네이티브 로그인 플러그인이 필요해요.
- 앞서 정리한 "앱이 닫히면 알림이 안 울린다" 문제도 로컬 알림(OS 예약)으로 서버 없이 해결돼요. (정확한 시각 알림은 Android 버전별 권한 제약이 있어 확인 필요)
- 같은 React 코드를 그대로 쓰고 데이터·로그인(Firebase)도 그대로예요. iOS는 나중에 같은 코드로 확장 가능(Apple 개발자 계정 연 비용 별도).

### 3-2. 광고 코드 구조 (미리 만들어 둘 것)

화면은 광고 회사가 무엇이든 모르게, **슬롯 한 종류만** 쓰게 해요.

```
<AdSlot placement="dashboard-side" />      ← 화면 코드는 이것만 안다
   └ src/ads/AdSlot.tsx   플랫폼 어댑터 선택: web(AdFit/AdSense) | native(AdMob)
   └ src/ads/placements.ts 위치 정의(크기·허용 화면)
   └ src/ads/consent.tsx   동의 상태 (동의 전에는 광고 요청 안 함)
   └ src/ads/rules.ts      adsAllowed(route, 상태) — 아래 '넣지 않는 곳'
```
- **광고 켜고 끄기(킬 스위치)**와 **광고 제거 사용자**를 위한 플래그를 처음부터 둬요 (나중에 구독 도입).
- 광고 요청에는 **아기 정보·계정 식별자를 절대 넘기지 않아요.** 광고 SDK와 사용자 데이터를 분리해요.
- 광고 자리 높이를 미리 확보해서 화면이 밀리지 않게 해요 (레이아웃 흔들림 방지).
- 지연 로딩: 광고 스크립트가 첫 화면을 늦추지 않게 해요 (앱은 오늘의 식단이 먼저 보여야 해요).

### 3-3. 광고 위치 지도

**넣어도 되는 곳 (콘텐츠 사이, 조작 버튼에서 떨어진 곳)**

| 화면 | 모바일 앱 | PC |
|---|---|---|
| 홈 | 영양 카드 아래 인라인 1개 | 대시보드 오른쪽 열 맨 아래 (300×250) |
| 성장 리포트 | 카드 사이 1개 | 오른쪽 열 하단 |
| 홈큐브·마일스톤 | 목록 아래 1개 | 오른쪽 열 하단 |
| 공개 가이드 페이지(신규) | 본문 중간·하단 | 본문 중간·오른쪽 |

**넣지 않는 곳**
- **로그인·가입·아기 정보 입력 화면**, 빈 상태·오류 화면 (콘텐츠 없는 화면의 광고는 정책 위반 소지)
- **모달·편집 창·출력 화면·인쇄물**
- **알레르기 테스트 안내·병원 안내 근처** (광고가 의료 권고처럼 보이면 안 돼요)
- **완료 토글, 큐브 ± 버튼, 하단 탭 바 바로 옆** (실수 클릭 유도는 광고 정책 위반 — 계정 정지 사유)
- 앱 시작 직후 전면 광고. 식사 시간에 급히 쓰는 앱이라 전면 광고는 이탈 위험이 커서, **처음엔 배너·네이티브만** 권장해요. 늘린다면 빈도 제한 + 작업이 끝난 자연스러운 지점에서만.

**광고 카테고리 차단 권장**: 분유·건강기능식품·의료/병원 광고는 앱의 건강 안내와 충돌하거나 규제 이슈가 있어 광고 관리 화면에서 막는 걸 권장해요 (수익은 줄 수 있음. 결정 사항).

### 3-5. 플레이스토어 진행 순서 (시간이 오래 걸리는 것부터)
1. 개발자 계정 만들기(1회 등록비). **개인 계정은 출시 전에 비공개 테스트를 일정 인원·기간(2025년 기준 12명, 14일) 거쳐야 해요** (확인 필요). → **이 기간이 일정의 병목**이라 일찍 시작하고, **맘카페에서 테스터를 모집**하면 PC 홍보와 겹쳐요.
2. 광고 수익이 생기면 **사업자 등록·세금 신고** 문제가 따라와요. 세무 전문가와 상의해요 (확인 필요).

### 3-6. 수익 감각 (가정치일 뿐, 예측이 아님)
```
일 수익 ≈ 일 사용자(DAU) × 1인당 광고 노출 수 × 노출 1,000회당 단가(eCPM) ÷ 1,000
```
예: DAU 1,000명 × 8회 × eCPM 1,500원(**가정**) ≈ 12,000원/일 ≈ 월 36만 원.
- 광고 단가는 지역·시기·카테고리로 크게 달라서 실제 값은 광고 콘솔에서 확인해야 해요.
- 그래서 **DAU(매일 쓰는 사람 수)가 곧 수익**이에요. 아래 추천 기능은 대부분 "매일·가족 단위로 쓰게 만드는" 것에 초점을 맞췄어요.
- 광고 외 수익원: ① **제휴 링크**(큐브 트레이·이유식 도구 — 육아 분야는 디스플레이 광고보다 단가가 높은 경우가 많음), ② **광고 제거 구독**(가족 공유 확장과 묶기). 둘 다 표기·정책 준수 필요.

## 4. 추천 기능 (우선순위)

### P0 — 출시 전에 반드시 (정책·안전)
1. **이용약관·개인정보 처리방침·민감정보 동의·첫 실행 면책 모달** (가입 흐름에 포함)
2. **회원 탈퇴 + 데이터 삭제** (앱 안 + 웹 링크)
3. **Firebase 실제 연동 검증**: 설정 → 모바일 가입 → PC 로그인 → 실시간 반영 → 보안 규칙 테스트
4. **자동 테스트(추천 규칙 불변조건)**: 새 재료 하나씩·3일 연속·반응 재료 제외·알레르기 자동 시작 금지. 건강 안전과 직결
5. **오류 수집**(Crashlytics/Sentry)과 **App Check**(남의 앱이 내 서버를 못 쓰게)
6. **데이터 백업·내보내기(JSON/CSV)** — 사용자 신뢰, 기기 변경 대응
7. **문의/피드백**(서버 함수로 이메일·텔레그램 전달)

### P1 — 매일·가족 단위로 쓰게 만드는 기능 (광고 노출·DAU ↑)
1. **가족 공유(공동 양육자 초대)** ★ 가장 효과 큼. 지금은 계정 1개 = 데이터 1벌이라 엄마·아빠·할머니가 따로 써요. 같은 아기 데이터를 초대 링크로 공유하면 DAU가 가구당 2~3배가 되고 "누가 먹였는지" 기록으로 이어져요. (데이터 구조를 계정 소유 → **아기(가구) 소유**로 바꿔야 하니 **일찍 결정**해야 해요)
2. **식단표 이미지 공유(카카오톡·카페용)**: 한 장짜리 PNG + 사이트 주소 워터마크. 맘카페에서 식단표를 사진으로 올리는 문화에 딱 맞고 **자연스러운 유입 통로**가 돼요. (출력/PDF는 이미 있음)
3. **병원 제출용 알레르기 기록 출력**: 알레르기 테스트 날짜·재료·반응 메모를 한 장으로. 월~수 테스트 설계와 이어지고 신뢰가 커요.
4. **로컬 알림 고도화**(Capacitor): 식사 10분 전, 알레르기 테스트 첫날 아침 안내, 큐브 기한 임박 아침 알림.
5. **월령 단계 전환 안내**: "이제 중기예요. 단계를 바꿀까요?" (지금은 프로필에서 수동)
6. **성장 기록(키·몸무게·머리둘레)**: 리포트 이름과 맞추기. 백분위 곡선은 공식 성장도표 데이터가 필요하니 **출처 확인 후**(CLAUDE.md 규칙), 처음엔 기록·선 그래프만.
7. **끼니 반응 한 줄(잘 먹음/조금/거부)**: 추천 알고리즘이 학습하는 데이터 ([RECOMMENDER_DESIGN.md](RECOMMENDER_DESIGN.md)).

### P2 — 수익·성장
1. **광고 슬롯 시스템 + 동의 화면** (§3-2)
2. **공개 콘텐츠 페이지**: 월령별 이유식 가이드·재료 도입 순서·큐브 만들기·자주 묻는 질문. **SEO 유입 + AdSense/AdFit 승인 + 광고 인벤토리**를 한 번에 해결해요. 건강 수치는 **출처 명시**(공공기관·학회) 규칙을 그대로 적용해요.
3. **체험 모드**(로그인 없이 이 기기에 저장): 카페 유입 PC 사용자가 가입 전에 써 보게 → 전환율 ↑ (이미 로컬 저장 구조라 비용이 작아요)
4. **제휴 링크**(장보기·큐브 화면의 "만들 때 필요한 도구") — 대가 표기 필수
5. **카카오·네이버 로그인**(서버 함수) — 한국 사용자 가입 전환에 유리
6. **광고 제거 구독 / 가족 공유 확장 요금제**
7. **익명 통계 기반 추천 보정**(GUIDE 2.2) — **별도 동의 + 방침 개정** 후에만

### 하지 않기를 권장
- 광고를 위한 **전면 광고 남발·가짜 닫기 버튼**: 삭제·낮은 평점으로 이어져요.
- 아기 정보를 **광고 타깃팅에 사용**: 정책·법적 위험이 매우 커요.
- 게임·포인트 같은 부가 기능: 지금 목적(식단 관리)과 거리가 멀어요.

## 6. 결정이 필요한 것

1. **PC에서도 가입을 허용할까요?** 지금은 "가입은 모바일에서만"(디자인 규칙). PC 배포가 맘카페 중심이면 **허용 또는 체험 모드를 권장**해요. (바꾸는 곳: `src/pages/login/PcLogin.tsx`의 `allowSignUp`)
2. **앱 래퍼: Capacitor(권장) vs TWA?** 광고·알림·구글 로그인 때문에 Capacitor를 권해요.
3. **자체 도메인을 살까요?** 광고 승인·신뢰·카페 홍보에 사실상 필요해요(무료 서브도메인은 광고 승인이 어렵다고 알려져 있음 — 확인 필요).
4. **광고 카테고리 차단 범위**(분유·건강기능식품·의료 등): 수익 vs 신뢰·규제 위험.
5. **가족 공유를 1.0에 넣을까요?** 데이터 구조 변경이 필요해서 늦을수록 비싸져요.
6. **개인 vs 사업자(법인/개인사업자) 계정**: Play 개인 계정은 비공개 테스트 요건이 있고, 광고 수익 세금 처리도 달라져요.

## 7. 지금 코드에서 광고 대비로 미리 해 둘 만한 작은 일
- 광고가 들어갈 **빈 자리 컴포넌트(`AdSlot`)**와 `adsAllowed()` 규칙만 먼저 만들어 두기 (광고 회사 없이도 위치·간격을 확정할 수 있어요)
- 완료 토글·큐브 ± 버튼 주변 **여백 규칙**을 슬롯 설계에 반영
- 공개 페이지용 라우트와 **`<meta description>`·OG 태그·robots/sitemap** 기본 세팅 (현재 없음)
- 인쇄 화면에는 광고가 절대 안 나오도록 `print:hidden` 규칙 고정
