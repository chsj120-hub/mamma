## 2. 문의·오류 확인 (P0-5, P0-7)
- 앱 안 "문의·오류 신고" → `feedback` 컬렉션(종류, 내용, 답받을 이메일(선택), 화면 주소, 브라우저 종류).
- 처리하지 못한 오류 → 자동으로 `errors` 컬렉션(오류 메시지, 스택 일부, 화면 주소, 브라우저 종류, 빌드 모드). 계정·아기 정보는 포함하지 않고 세션당 5건까지, 같은 메시지는 한 번만 보내요.
- 확인: Firebase 콘솔 → Firestore → 컬렉션. **주 1~2회** 확인하고, `errors`는 90일, `feedback`은 처리 뒤(최대 1년) 지워요(방침에 적어 둔 기간). 지우는 일은 지금은 수동이에요.
- **텔레그램 알림**은 `docs/NOTIFY_SETUP.md`의 방식(GitHub Actions가 15분마다 확인, 무료)으로 켤 수 있어요. 즉시 알림(Cloud Functions)은 Blaze 요금제가 필요해요. 수익이 생긴 뒤에 `feedback`·`errors` 생성 시 실행되는 함수로 붙이고, 토큰은 함수의 비밀 설정에만 둬요(클라이언트 코드에 넣지 않아요).
- 개발 환경(Firebase 설정 없음)에서는 이 기기 저장소(`dev-feedback`, `dev-errors`)에만 남아요.

## 3. App Check (P0-5)
남의 사이트·스크립트가 내 Firebase를 마음대로 쓰지 못하게 하는 장치예요(무료).
1. 콘솔 → App Check → 앱 등록 → **reCAPTCHA v3** → 사이트 키 발급.
2. `.env.local`과 Vercel 환경변수에 `VITE_FIREBASE_APPCHECK_KEY=<사이트 키>` 추가 후 다시 배포.
3. 로컬 개발: 콘솔에 **디버그 토큰**을 등록(개발 서버를 열면 브라우저 콘솔에 토큰이 출력돼요).
4. 앱에서 정상 동작을 확인한 뒤 콘솔에서 **Firestore '시행'**을 켜요. 키 없이 시행부터 켜면 앱이 막혀요.
5. 승인된 도메인(`Authentication → 설정`)에 자체 도메인을 구매하면 추가해요.

## 4. 가족 공유 (P1-1) 동작
```
users/{주인uid}/data/*        기록 (주인과 구성원이 읽고 쓴다)
users/{주인uid}/members/{uid}  구성원 (초대 코드로 참여한 사람, 주인이 내보낼 수 있음)
users/{내uid}.householdId      내가 쓰는 기록의 주인 (없으면 나)
invites/{코드}                 초대 코드 (7일, 만든 사람만 삭제, 코드를 아는 사람만 하나씩 읽기)
```
- 초대: 프로필 수정 → 가족과 함께 쓰기 → 초대 코드 만들기 → 메신저로 전달.
- 참여: 받은 사람이 로그인 후 같은 곳에서 코드 입력 → **이 기기의 기록이 초대한 사람의 기록으로 바뀜**(내 예전 기록은 서버에 남아, 나가면 다시 보임).
- 내보내기·나가기·탈퇴: 구성원 본인이 나가거나 주인이 내보낼 수 있어요. 주인이 탈퇴하면 구성원 정보도 같이 지워지고, 구성원은 다음 접속 때 자기 기록으로 돌아와요. 구성원이 탈퇴하면 주인의 기록은 그대로예요.
- 알아 둘 것: 같은 기록을 여럿이 고치면 **마지막 저장이 이겨요**(실시간 반영 덕에 거의 안 겹쳐요). "누가 먹였는지" 표시는 아직 없어요(다음 개선).
- 확인 못 한 것: 실제 Firebase에서 두 계정으로 한 흐름은 이 환경에서 못 해 봤어요(가짜 로그인으로 참여·나가기·기록 교체만 확인). 체크리스트 10번으로 확인해 주세요.
