# 웹앱 전용 수익화 설계 (적자 없는 방향)

전제: **스토어 앱·설치 없음.** 링크·도메인으로 접속하는 웹앱(PC·모바일 공용)이고, 지금은 무료 주소(`*.vercel.app`)로 테스트 중이에요. 자체 도메인은 시범 운영 뒤에 구매해요. 단가·정책·세금은 자주 바뀌니 **"확인 필요"** 표시는 신청 전에 공식 문서로 꼭 확인해 주세요. 법률·세무 자문이 아니에요.

## 1. 원칙: 돈이 먼저 나가지 않게

| 원칙 | 방법 |
|---|---|
| 서버비가 0원에서 시작 | Firebase **Spark(무료) 요금제 유지**. 무료 한도를 넘으면 청구되는 게 아니라 **요청이 막혀요**(= 적자가 구조적으로 불가능). 한도 안에서 쓰다가 수익이 생기면 Blaze로 올려요 |
| Cloud Functions·푸시 등 Blaze가 필요한 기능은 미룸 | 수익이 비용을 넘은 뒤에 (닫힌 앱 푸시, 문의 알림 자동화) |
| 고정비를 단계별로 쓴다 | 도메인은 **조건을 채운 뒤에** 구매 (§4 게이트) |
| 광고는 승인 조건을 갖춘 뒤에 | 로그인 뒤 화면만으로는 승인이 어려워서 **공개 콘텐츠 페이지**가 먼저 (§3) |

| 항목 | 금액 | 비고 |
|---|---|---|
| 자체 도메인 | 연 1~3만 원대 (.com/.kr 등 종류별 상이) | 시범 운영 뒤 구매 |
| 호스팅 | **Vercel 무료(Hobby)는 비상업 용도로 약관에 제한이 있어요 — 광고를 붙이면 상업 용도로 볼 수 있어 확인 필요.** 대안: Cloudflare Pages·Netlify 등 상업 이용이 가능한 무료 플랜(확인 필요), 또는 Vercel Pro(월 약 $20) | **광고를 켜기 전에** 호스팅 약관부터 확인 |
| Firebase | 0원 (Spark) | 한도 §2 |
| 합계 | **월 0~수천 원 (Pro를 쓰면 약 3만 원)** | |

## 2. Firebase 무료 한도 안에서 얼마나 쓸 수 있나 (대략치)
Spark 일일 무료 한도(확인 필요): 읽기 5만 · 쓰기 2만 · 삭제 2만 · 저장 1GiB.

- 접속 1회 = 읽기 약 6~10건(기록 문서 6개 + 실시간 구독 변경분)
- 식단을 고칠 때마다 0.8초 뒤 바뀐 문서만 저장 → 하루 사용자 1명이 쓰기 약 10~30건
- 따라서 **하루 활성 사용자(DAU) 약 700~2,000명까지는 무료 한도 안**일 가능성이 커요. 가족 공유로 한 가구가 2~3명이 되면 읽기가 늘어요(실시간 구독).
- 한도에 다가가면: 저장 간격을 0.8초 → 3초로 늘리기(코드 한 줄, `AuthProvider.tsx`의 `DEBOUNCE_MS`), 가족 구독을 앱이 보일 때만 켜기. 그래도 부족하면 그때 Blaze로 올리고 **예산 알림**을 걸어요.
- 한도가 막히면 저장이 실패해요(앱은 기기 저장으로 계속 동작하고 오류 표시만 떠요). 콘솔 → 사용량에서 주 1회 확인.

## 3. 광고 설계 (웹앱 전용, 신뢰·규제 위험을 줄이는 방향)

### 3-1. 광고 회사 선택
| | 특징 | 메모 |
|---|---|---|
| **카카오 AdFit** | 국내 소형 사이트에 흔함, 한국 광고주 | 심사에 자체 도메인·콘텐츠 필요 (확인 필요) |
| **Google AdSense** | 단가·광고주 풍부, 차단 도구가 세밀 | 승인에 도메인·충분한 콘텐츠·개인정보 처리방침 필요. 로그인 뒤 화면은 심사 크롤러가 못 봐서 **공개 페이지 필수** |
| 제휴 링크(쿠팡 파트너스 등) | 육아 도구(큐브 트레이·이유식 용기)와 궁합이 좋음 | **대가 표기 의무**. 광고처럼 보이지 않게 "제휴 링크" 표시 |

처음엔 **한 곳만** 신청해요(AdSense 또는 AdFit). 둘을 번갈아 붙이는 건 승인 뒤에.

### 3-2. 광고가 들어가는 곳
- **공개 콘텐츠 페이지(신규, 가장 중요)**: 월령별 이유식 가이드, 재료 도입 순서, 큐브 만들기·보관, 자주 묻는 질문. 검색·맘카페 유입의 입구이면서 광고 심사 대상이에요. 건강 수치는 CLAUDE.md 규칙대로 **출처(공공기관·학회)를 적고**, 없으면 넣지 않아요.
- **앱 안(로그인 뒤)**: 홈·리포트·큐브·마일스톤 화면의 카드 사이 1~2칸 (PC는 오른쪽 열 맨 아래 300×250).
- **넣지 않는 곳**: 로그인·가입·동의·아기 정보 입력, 모든 창(모달·시트), 출력·이미지 공유, 알레르기 테스트 안내·병원 안내 주변, 완료 토글·큐브 ± 버튼 근처(실수 클릭 유도는 정책 위반), 오류·빈 화면, 전면 광고.
- 구현 방식: `AdSlot` 하나만 화면에 쓰고(광고 회사를 화면 코드가 모름), `adsAllowed(경로)` 규칙과 **킬 스위치**(환경변수 하나로 전체 끄기)를 둬요. 광고 자리 높이를 미리 잡아 화면이 밀리지 않게 하고, 첫 화면이 뜬 뒤에 지연 로딩해요. *(아직 코드 없음 — 승인이 날 때 만들어요. 승인 전에 만들면 빈 자리만 생겨요.)*

### 3-3. 광고 카테고리 차단 (수익이 줄어도 신뢰·규제 우선)
광고 관리 화면(AdSense: 광고 검토 센터 → 차단 관리, AdFit: 광고 차단 설정)에서 아래를 막아요. 이름은 콘솔마다 달라 가장 가까운 항목으로 고르세요(확인 필요).

| 차단 | 이유 |
|---|---|
| **분유·조제식·이유식 업체 광고, 건강기능식품·영양제** | 이 앱의 식단 안내와 충돌해 "추천"처럼 보일 수 있고 표시·광고 규제가 있어요 |
| **의료·병원·한의원·약품·치료·시술** | 의료 권고로 오해될 수 있고 의료광고 규제 대상 |
| **다이어트·성형·미용 시술** | 육아 앱 신뢰와 거리가 멀고 심의 이슈 |
| **금융(대출·보험·투자·가상자산)** | 사기·규제 위험이 큰 분야 |
| **성인·도박·주류·담배·사행성 게임** | 부모 대상 앱에 부적합 |
| **정치·종교·선정적·충격적 이미지** | 분쟁·불쾌감 |
| **'민감한 카테고리' 전체**(AdSense 설정 화면에 있어요) | 한 번에 막을 수 있는 가장 간단한 방법 |

추가 설정:
- **맞춤 광고 끄기(비맞춤 광고만)**: 이용자의 행동·관심을 광고에 쓰지 않아 동의·규제 부담이 줄어요. 수익은 줄어요(수용). 방침 7항에 명시.
- **아기·건강 정보는 광고 요청에 절대 넘기지 않아요.** 광고 스크립트는 로그인한 사용자 식별자·기록과 분리해요.
- 광고 위에 **"광고"** 표시. 광고를 켜는 순간 방침을 고치고 `LEGAL_VERSIONS`를 올려 재동의를 받아요.
- 이 앱은 **부모(성인) 대상 서비스**로 광고 회사에 신고해요(아동 대상으로 분류되면 제약이 커져요).
- 신고 창구: 광고 품질이 이상하면 콘솔에서 해당 광고주·URL을 즉시 차단해요(주 1회 점검).

## 4. 단계와 게이트 (조건을 채우면 다음으로)

| 단계 | 하는 일 | 비용 | 다음 단계로 가는 조건(제안) |
|---|---|---|---|
| **T. 테스트** (지금) | 무료 주소, 광고 없음, 지인·소수 테스트. Firebase 실연동 확인(`docs/OPERATIONS.md` 체크리스트), 오류·문의 모으기 | 0원 | 체크리스트 통과, 치명 오류 없음, 테스터 10가구 이상이 2주 사용 |
| **S. 시범 운영** | 맘카페·지인 공유로 유입 시험. 이미지 공유(워터마크)·링크 공유 활용. 공개 콘텐츠 페이지 10~20개 작성 시작 | 0원 | **주간 활성 가구가 꾸준히 늘고(예: 100가구 이상) 2주 이상 유지**, 재방문이 있을 것 |
| **D. 도메인 구매** | 자체 도메인 구매 + 연결, 방침·약관의 운영자 정보 확정, 호스팅 약관 확인 | 연 1~3만 원 | 위 조건 충족. 도메인은 **한 번 정하면 바꾸기 어려우니** 앱 이름과 검색에서 겹치지 않게 |
| **A. 광고 신청** | 공개 페이지 20개 이상 + 개인정보 처리방침으로 AdSense/AdFit 신청, 승인되면 `AdSlot` 구현·차단 설정 | 0원 (호스팅이 Pro면 월 약 3만 원) | 승인 |
| **R. 수익 최적화** | 제휴 링크, 가족 공유로 DAU↑, 필요하면 Blaze + 푸시 | 수익 안에서 | 월 수익이 월 비용의 2배 넘으면 유료 기능 검토 |

**손익분기 감각**: 월 비용 3만 원(Pro 가정)을 광고로 메우려면 일 약 1,000원이 필요해요. 예시(**모두 가정**): 1인당 하루 4번 광고 노출, 1,000회 노출당 수익(RPM) 1,500원이면 **DAU 약 170명**. 호스팅이 무료면 도메인(월 약 1,500원)만 메우면 돼서 DAU 약 10명 수준이에요. 광고 단가는 시기·카테고리에 따라 크게 달라서(차단을 많이 하면 낮아져요), 승인 뒤 첫 달 실측으로 다시 계산해요.

## 5. 광고 말고 수익이 되는 것 (웹앱에 맞는 순서)
1. **제휴 링크**: 큐브 트레이·이유식 용기·보관팩 등 *실제로 만들 때 필요한 도구* 소개. 홈큐브 화면 "만들 때 필요한 도구"(광고 아님, "제휴 링크로 수수료를 받아요" 표기).
2. **가족 공유가 DAU를 키움**: 한 가구가 2~3명이 쓰면 노출이 늘어요. (구현됨)
3. **이미지 공유 워터마크**: 맘카페에 올린 식단표 이미지의 주소가 자연 유입 통로. (구현됨)
4. **광고 제거·후원**(나중): 결제 연동(PG)·사업자·환불 정책이 필요해서 수익이 안정된 뒤에. 지금은 하지 않아요.

## 6. 법·세무 체크 (확인 필요)
- 광고·제휴 수익이 생기면 **사업자 등록 여부와 소득 신고**가 필요해질 수 있어요(개인이어도 수익이 반복되면 사업소득으로 볼 수 있음). 세무사·국세청 안내를 확인하세요.
- 제휴 링크는 대가 표기 의무(공정위 지침). 광고는 "광고" 표기.
- 방침·약관의 운영자 정보(`src/data/legal.ts`)는 실제 운영자 이름·이메일·보호책임자로 채워야 해요. 사업자 등록을 하면 상호·번호를 같이 적어요.
- 설치형 앱 심사가 없는 대신, **웹에서 아기 건강 정보를 다루므로** 민감정보 동의·탈퇴·삭제 경로(구현됨)와 App Check·규칙(아래 문서)을 유지해요.
