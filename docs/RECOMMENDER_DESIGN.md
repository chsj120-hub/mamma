# 식단 추천 알고리즘 설계안

목표: **시기별 기초 데이터를 뼈대로** 삼고, **이미 입력한 식단·기록을 읽어서** 다음 식단을 이어서 추천한다.
원칙: ① 안전 규칙은 점수로 타협하지 않는다 ② 같은 입력이면 같은 결과(재현 가능) ③ 모든 추천에 이유를 붙인다.

## 1. 지금 구조의 한계 (`src/lib/recommender.ts`)

지금은 날짜를 하루씩 채우면서 규칙을 순서대로 적용하는 **한 번 훑는 규칙 엔진**이에요. 안전 규칙(3일 테스트·새 재료 하나씩·반응 재료 제외)은 이미 잘 지켜요. 한계는 다음과 같아요.

| 한계 | 증상 |
|---|---|
| 먹은 양·거부 기록을 안 읽음 | 아기가 안 먹는 재료도 똑같이 계속 나와요 |
| 재료 선택이 `n % 개수` 순환 | 최근에 뭘 먹었는지가 아니라 날짜 숫자로 정해져요 |
| 주간 균형(철분·채소 종류·분류)을 하루 단위로만 봄 | 한 주를 다 채운 뒤 보면 과일이 없거나 한 채소만 반복될 수 있어요 |
| 냉동 큐브 재고를 안 읽음 | 임박한 큐브가 있어도 다른 재료를 추천해요 |
| 이유를 설명하지 않음 | 왜 이 메뉴인지 부모가 알 수 없어요 |

## 2. 제안: 4단 파이프라인

```
[A] 기초 데이터(시기별)  ─┐
[B] 내 기록(식단·반응·재고) ─┼─▶ [1] 후보 거르기 ─▶ [2] 새 재료 정하기 ─▶ [3] 점수로 채우기 ─▶ [4] 주간 점검·보정 ─▶ 식단 + 이유
```

### [A] 기초 데이터 (사람이 관리, 출처 규칙 적용)
- `src/data/stageGuide.ts`: 단계별 하루 횟수·한 끼 재료 수·식감
- `src/data/ingredientIntro.ts`: 재료를 시작하는 단계와 순서
- 이 값만 바꾸면 추천이 따라 바뀌게 유지해요. 건강 수치는 출처 확인 후에만 넣는다는 규칙(CLAUDE.md)을 그대로 지켜요.

### [B] 내 기록 (이미 있는 데이터 + 아래 추가분)
| 이미 있음 | 새로 필요 |
|---|---|
| 날짜별 식단, 완료 여부, 먹은 양(ml) | **끼니별 반응 한 줄**: 잘 먹음 / 조금 먹음 / 거부 (먹은 양과 별개, 선택 입력) |
| 반응 있었던 재료(`reactions`) | 재료별 **수용도 통계**(아래 3.3) — 기록에서 계산하는 파생값이라 저장하지 않아요 |
| 냉동 큐브 재고·소비기한 | 부모가 식단을 **직접 고친 내역**(추천을 바꿨다는 신호) — 스냅샷으로 이미 일부 남아요 |

### [1] 후보 거르기 — 하드 규칙 (위반하면 후보에서 제거)
점수와 무관하게 먼저 걸러요. 여기서 걸러진 재료는 어떤 점수로도 되살아나지 않아요.
1. 아기의 현재 단계까지 열린 재료만 (`ingredientIntro`)
2. 반응 있었던 재료 제외
3. 섞는 재료는 **3일 테스트를 통과한 것만**
4. 테스트 중인 새 재료는 하루에 한 가지, 첫 끼에, 3일 연속 (지금 구현 유지)
5. 알레르기 재료는 자동으로 시작하지 않음 → "시작할 시기예요" 안내 (지금 구현 유지)
6. 한 끼 재료 수는 단계별 상한 이하

### [2] 새 재료 정하기 (도입 스케줄러)
- 기본: `ingredientIntro` 순서대로 다음 재료.
- **개인화 보정**: 거부 기록이 있는 재료는 며칠 간격을 두고 다시 시도하는 후보로 올려요(새 음식은 여러 번 시도해야 익숙해진다는 안내와 연결).
- 한 번에 새 재료는 하나, 테스트가 끝난 날 바로 다음 재료를 시작해요(빈 날 없이 이어지게).

### [3] 점수로 채우기 (핵심 개선)
슬롯(날짜 × 끼니 × 칸)을 **고기 → 채소 → 과일** 순서로 채우되, 후보마다 점수를 매겨 가장 높은 것을 골라요.

```
점수 = w1·다양성 + w2·영양 균형 + w3·수용도 + w4·재고 + w5·변화(새 맛) − 반복 패널티
```

| 요소 | 계산 방법(예) | 읽는 데이터 |
|---|---|---|
| **다양성** | 최근 7일 사용 횟수가 적을수록 가산, 어제 먹은 재료는 큰 감점 (최근일수록 가중, 지수 감쇠) | 기 입력 식단 |
| **영양 균형** | 이번 주에 아직 부족한 분류(과일·채소 종류·단백질 종류)를 채우는 재료 가산 | 기 입력 식단 + 이번 주 계획 |
| **수용도** | 그 재료가 든 끼니의 `먹은 양 ÷ 목표량` 평균(데이터가 적으면 전체 평균 쪽으로 당기는 **베이지안 평활**), 거부 기록은 감점 | 먹은 양·반응 기록 |
| **재고** | 소비기한 임박 큐브 가산, 재고 없는 재료는 약한 감점 | 홈큐브 |
| **변화** | 막 통과한 재료를 한두 번 더 쓰게 약한 가산 | 도입 기록 |

- **같은 점수면 결정적 규칙으로 정렬**(재료 순서)해서 항상 같은 결과가 나와요. 필요하면 "다른 조합 보기" 버튼이 시드 값을 바꿔 상위 후보 사이에서 고르게 할 수 있어요.
- 가중치 `w1~w5`는 **튜닝 값**(의학 기준이 아님)이라 한 파일(`src/data/recommenderWeights.ts`)에 모아요. 의학적 임계값(철분 주 목표 일수 등)은 가중치와 분리하고, 출처 확인 후에만 넣어요.

### [4] 주간 점검·보정
하루씩 채운 결과를 한 주 단위로 다시 검사하고, 부족하면 점수가 가장 덜 중요한 칸 하나를 바꿔요.
- 철분(소고기 등) 포함 일수가 목표보다 적으면 단백질 칸을 교체
- 채소 종류가 너무 적으면 반복된 채소를 다른 통과 재료로 교체
- 교체해도 [1]의 하드 규칙은 깨지 않아요

### 설명(이유) 만들기
각 슬롯을 고른 **가장 큰 점수 요소 1~2개**를 이유로 저장해요. 예: "어제와 겹치지 않아요", "소고기 큐브가 D-2라 먼저 썼어요", "이번 주 과일이 아직 없어요", "지난 3번 잘 먹었어요". 식단 카드에 작게 보여 주면 부모가 이해하고 직접 고치기도 쉬워요.

## 3. 사용자가 고친 식단을 어떻게 읽나

- 부모가 추천을 **바꾼 재료는 약한 선호 신호**(+/−)로 반영해요. 한 번 바꿨다고 영구 제외하지 않고 점수만 조금 움직여요.
- 직접 입력한 식단(편집·CSV)은 "기 입력"으로 보고 다음 추천의 시작 조건으로 써요. 예를 들어 CSV로 넣은 다음 주 월~수가 있으면, 목~일만 이어서 채우되 월~수와 겹치지 않게 해요.
- 이미 입력된 날은 덮어쓰지 않아요(지금과 동일).

## 4. 개인화 단계 (복잡도를 천천히 올리기)

| 단계 | 내용 | 필요한 것 |
|---|---|---|
| **1단계** (바로 가능) | 위 파이프라인, 고정 가중치, 이유 표시 | 기존 데이터 + 끼니 반응 한 줄 |
| **2단계** | 아기별 가중치 미세 조정(잘 먹는 분류 쪽으로) | 몇 주 치 기록 |
| **3단계** | 여러 가정의 **익명 집계**로 도입 순서·단계 전환 시기 보정 (GUIDE.md 2.2) | 서버 저장 + **명시적 동의** + 개인정보 처리방침 |

머신러닝 모델은 필요 없어요. 데이터가 적은 초기에는 규칙 + 점수가 더 안전하고 설명하기 쉬워요.

## 5. 안전장치와 테스트

- **불변조건 테스트**: 12주 가상 기록으로 추천을 돌려서 "새 재료 하나씩·3일 연속", "반응 재료 없음", "한 끼 재료 수 상한", "알레르기 자동 시작 없음"이 한 번도 깨지지 않는지 확인해요.
- **재현성 테스트**: 같은 입력 → 같은 출력.
- **품질 지표**: 주간 분류 균형, 연속 중복 횟수, 임박 큐브 소진율을 시뮬레이션으로 비교해 가중치를 조정해요.
- 건강 관련 문구에는 "참고용, 소아청소년과와 상의" 안내를 유지해요.

## 6. 구현 순서 제안

1. 끼니 **반응 한 줄**(잘 먹음/조금/거부) 입력 추가 — 홈 카드와 식단 편집 창
2. `src/lib/recommend/`로 분리: `candidates.ts`(하드 규칙) → `introduce.ts`(새 재료) → `score.ts`(점수) → `repair.ts`(주간 보정) → `explain.ts`(이유)
3. 가중치 파일 + 불변조건·재현성 테스트(시뮬레이터)
4. 식단 카드에 이유 표시, "다른 조합 보기"
5. (선택) 2~3단계 개인화

## 7. 결정이 필요한 점

- 재고 연동을 얼마나 강하게 할지: **약하게**(임박 큐브만 가산) vs **강하게**(재고 있는 재료 위주로만 추천)
- 거부한 재료를 다시 시도하기까지의 간격(며칠)과 횟수 — 기준을 정하려면 소아과 확인이 필요해요
- 끼니 반응 입력을 필수로 둘지 선택으로 둘지(부담 vs 정확도)
