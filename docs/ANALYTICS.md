# 활성 가구 측정 (방문 분석 B + 접속일 기록 C)

## 무엇을 재나
| | 방법 | 알 수 있는 것 |
|---|---|---|
| B. 방문 분석 | Cloudflare Web Analytics (쿠키 없음) | 방문자 수, 페이지별 조회, 유입 경로(카페·검색·직접) |
| C. 접속일 기록 | 앱이 하루 한 번 `activity/{날짜}_{가구}` 문서를 남김 | **주간 활성 가구**, 일간 활성 가구, 다음 주 재방문율 |

식단·큐브 내용은 읽지 않아요. 남는 건 날짜와 가구 식별값뿐이고 90일 뒤 자동으로 지워져요. (방침에 반영됨, 동의 버전을 올려서 테스터는 다음 접속 때 다시 동의 화면이 나와요.)

## 1회 설정
1. **규칙 게시**: `firestore.rules`를 콘솔 → Firestore → 규칙에 붙여넣고 게시 (`activity` 컬렉션 규칙이 새로 들어갔어요).
2. **90일 삭제**: TTL 정책은 Firebase 콘솔이 아니라 **Google Cloud 콘솔**(Firestore → Time-to-live)에서 만들어요(컬렉션 그룹 `activity`, 필드 `expireAt`). 권한 오류(403)로 안 되면 대체: 한 달에 한 번 `npm run stats -- --key "키경로" --prune`을 실행해 만료된 기록을 지워요. 둘 중 하나는 꼭 해야 방침의 90일을 지킬 수 있어요.
   - PowerShell에서 `npm`이 "스크립트를 실행할 수 없습니다"(실행 정책)라고 하면 `npm.cmd run stats -- --key ...`로 실행하거나, 명령 프롬프트(cmd)를 써요.
3. **방문 분석(선택)**: Cloudflare 대시보드 → Web Analytics → 사이트 추가 → 호스트 이름 입력 → 나오는 토큰을 `VITE_CF_ANALYTICS_TOKEN`으로 Vercel/Cloudflare Pages 환경변수와 `.env.local`에 넣고 재배포. 도메인을 바꾸면 사이트를 새 호스트 이름으로 다시 추가해요. 개발 서버(`npm run dev`)에서는 켜지지 않아요.

## 숫자 보는 법 (운영자 PC에서)
1. 콘솔 → 프로젝트 설정 → **서비스 계정** → "새 비공개 키 생성" → JSON 파일 저장. **이 파일은 비밀번호와 같아요.** 프로젝트 폴더 밖(예: 문서 폴더)에 두고 git에 올리지 마세요(`serviceAccount*.json`은 `.gitignore`에 있어요).
2. 프로젝트 폴더에서:
   ```bash
   npm run stats -- --key "C:\경로\serviceAccount.json"
   ```
3. 출력 예: 가입 계정 수, 최근 14일 일간 활성 가구, 최근 8주 주간 활성 가구, 주별 신규 가구의 다음 주 재방문율.

기록은 이 기능을 배포한 날부터 쌓여요. 처음 몇 주는 숫자가 작게 보이는 게 정상이에요.

## 추천(공유) 링크 유입 보는 법
공유 버튼이 보내는 링크는 `주소/r/<출처>` 모양이에요. 로그인한 사람은 바로 `/`로 돌아가고, 방문 한 번은 방문 분석에 `/r/…` 경로로 남아요.

| 경로 | 뜻 |
|---|---|
| `/r/share-guide` | 가이드 글 아래 "친구에게 맘마 추천하기" |
| `/r/share-settings` | 프로필(설정) 화면의 추천하기 |
| `/r/share-login` | 로그인 화면의 추천하기 |
| `/r/qr` | "휴대폰에서 열기" QR을 찍고 들어옴 |

**보는 곳**: Cloudflare 대시보드 → Web Analytics → 해당 사이트 → **Paths**(경로) 표에서 `/r/`로 시작하는 줄을 찾아요. 방문 수와 방문자 수가 나와요.
- 링크에 개인 정보는 들어 있지 않아요. 누가 보냈는지는 알 수 없고 "어느 버튼에서 퍼졌는지"만 세요.
- 가입으로 이어졌는지는 이 표로 알 수 없어요. 가입 계정 수 증가(`npm run stats`)와 날짜로 대조해서 추측해요.
- 개발 서버와 토큰 설정 전에는 기록되지 않아요. 도메인을 바꾸면 경로는 같아도 새 사이트에서 따로 쌓여요.

## 판단 기준 (제안)
- 도메인 구매: 주간 활성 가구가 꾸준히 늘고(예: 100가구) 2주 이상 유지.
- 재방문율이 낮으면 홍보보다 제품 개선이 먼저예요. 유입 경로는 B에서 봐요.
- 한도: 가구당 하루 쓰기 1건이라 Firestore 무료 한도(Spark)에 거의 영향이 없어요.
