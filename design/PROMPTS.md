## B. PC 화면

### B-1. 반응형 기반 + 공통 레이아웃
```
이제 PC 화면을 추가할 거야. design/README.md 의 'PC 레이아웃 규칙'과
design/screens/Desktop.dc.html 을 참고해서:
1) 화면 폭 1024px 이상이면 PC 레이아웃, 미만이면 기존 모바일 레이아웃이 나오게 해줘.
2) PC 공통 레이아웃 컴포넌트 <DesktopLayout> 를 만들어줘:
   왼쪽 사이드 메뉴(로고, 식단 플래너·홈큐브 보관함·성장 리포트·마일스톤 메뉴, 테마 선택 3종, 프로필 카드)
   + 오른쪽 본문(최대 폭 1200px, 여백 32px).
3) 라우팅은 react-router 로 /, /cube, /report, /milestone 을 모바일·PC가 같이 쓰게 해줘.
모바일에서 이미 만든 데이터 저장 로직과 컴포넌트(재료 아이콘, 상태 배지)는 새로 만들지 말고 재사용해줘.
```

### B-2. PC 대시보드
```
design/screens/Desktop.dc.html 을 보고 PC 대시보드(/)를 만들어줘.
- 상단: 날짜, D+일수, AI 추천으로 채우기 / 알레르기 재료 대체 / 실행취소 / 출력 버튼
- 유통기한 임박 알림 배너
- 월간 캘린더: 칸 맨 위 날짜와 완료 점, 그 아래 재료 아이콘+이름 세로 목록,
  알레르기 테스트는 칸 맨 아래 한 줄 (날짜 옆에 두지 말 것). 베이스 쌀은 칸에서 생략.
- 오른쪽: 오늘의 식단(완료 토글), 홈큐브 확인 필요, 이번 주 영양 균형
식단 데이터는 모바일 플래너와 같은 저장소를 써줘.
```

### B-3. PC 홈큐브 보관함
```
design/screens/PcCube.dc.html 을 보고 /cube 의 PC 화면을 만들어줘.
- 숫자 카드 4개(보관 중, 재고 부족, 기한 임박, 이번 주 사용 예정)는 실제 데이터로 계산
- 재고 표: 재료(아이콘), 분류, 수량(−/+ 버튼), 제조일, 소진 기한(D-n), 상태
- 소진 기한 = 제조일 + 권장 보관 기간(고기·생선 21일, 채소·과일·곡물 14일)
- 수량 2개 미만이면 '재고 부족', 기한 3일 이내면 '기한 임박' (임박이 우선)
- 분류 탭 필터, 재료 검색, 오른쪽 장보기 목록(재고 부족 큐브 자동)
- 큐브 추가 버튼은 모달로 (재료, 수량, 제조일 입력)
```

### B-4. PC 성장 리포트

## C. 로그인

규칙: 가입은 휴대폰(모바일 화면)에서만. PC 화면에서는 이미 가입한 계정만 로그인.
처음엔 가짜 로그인(C-1)으로 화면 흐름부터 완성하고, 실제 연동(C-2, C-3)은 나중에 붙이세요.

### C-1. 로그인 화면 + 가짜 로그인
```
design/screens/AppLogin.dc.html 과 design/screens/PcLogin.dc.html 을 보고 로그인 화면을 만들어줘.
- 로그인 안 된 상태에서 접속하면 모바일 폭은 AppLogin, PC 폭(1024px 이상)은 PcLogin 화면을 보여줘.
- 버튼 3개: 카카오, 네이버, Google. 왼쪽 로고 자리는 src/assets/social/ 의 이미지를 쓰게 하고,
  이미지가 없으면 빈 자리로 둬. (공식 로고는 내가 각 개발자 사이트에서 받아서 넣을게)
- 지금은 실제 연동 없이 가짜 로그인(mock)으로 동작하게 해줘:
  · 모바일에서 버튼을 누르면 → 계정이 없으면 새로 만들고(가입) → 아기 정보 입력 화면 → 홈
  · PC에서 버튼을 누르면 → 가입된 계정이면 대시보드, 없으면 PcLogin 의
    '아직 가입되지 않은 계정이에요' 안내 표시 (PC에서는 절대 새 계정을 만들지 않음)
- 인증 로직은 src/auth/ 폴더에 authService 인터페이스로 분리해서,
  나중에 mock 을 실제 Firebase 로 바꿀 때 화면 코드는 안 고쳐도 되게 해줘.
- 로그아웃 버튼은 PC 사이드 메뉴 프로필 카드와 모바일 설정에 넣어줘.
```

### C-2. 실제 연동 — Google (Firebase Auth)
```
Firebase 프로젝트를 만들었어. (설정값은 .env 에 넣을게)
authService 의 Google 로그인을 Firebase Auth 로 바꿔줘.
- 모바일 가입 시 Firestore users/{uid} 문서를 만들고 (가입일, 가입 경로, 아기 프로필)
- PC 로그인 시 users/{uid} 문서가 없으면 바로 로그아웃시키고 '가입되지 않은 계정' 안내를 띄워줘.
- 같은 규칙을 Firestore 보안 규칙에도 반영해줘.
Firebase 콘솔에서 내가 직접 눌러야 하는 설정이 있으면 순서대로 알려줘.
```

### C-3. 실제 연동 — 카카오·네이버
```
카카오와 네이버 로그인을 authService 에 붙여줘.
Firebase Auth 가 기본으로 지원하지 않으니, 어떤 방식이 초보자에게 가장 단순한지 먼저 비교해서 알려주고
(예: Cloud Functions 로 커스텀 토큰 발급, 또는 OIDC 연동), 내가 고른 방식으로 구현해줘.
카카오 디벨로퍼스·네이버 디벨로퍼스에서 내가 해야 할 설정(앱 등록, Redirect URI, 키 발급)도 순서대로 알려줘.
비밀 키는 절대 프론트엔드 코드에 넣지 말고 서버(Functions) 환경변수로 관리해줘.
```
